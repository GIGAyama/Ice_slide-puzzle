## note に貼る手順

1. note で新しい記事を作り、1行目の見出しを記事のタイトル行にします。
   `# 教室で使えるかもしれないもの作り ...` の `#` は貼らず、note のタイトル欄に入れます
2. 本文を貼ります。見出しは `##` のまま貼れば note 側で大見出しになり、目次が自動で作られます
3. 画像は自動で入りません。`![...](images/xx.png)` の行が出てきたところで、
   その名前の画像を手で上げてください。対応は下の一覧のとおりです
4. 画像のすぐ下にある一行は、note のキャプション欄に移します。本文には残しません
5. ハッシュタグは note の入力欄で付けます。本文には書いていません
6. 冒頭の URL は、貼るとカード表示になります。そのままで問題ありません

## 記事に書いた数字の出どころ

| 記事の記述 | 出どころ |
|---|---|
| 5かける5の25マス | `app.js` の `BOARD_SIZE = 5` |
| コマは5つずつ、王冠は各1つ | `app.js` の `initGame()` の初期配置 |
| 覚えることは3つ | `app.js` の `showRules()` のカード3枚 |
| 両チーム合わせて7手で決まった | 撮影シナリオで実際に指した手数（1手目から7手目） |
| 許可が要るかもしれないアドレスは3つ | `index.html` と `app.js` から外へ出る先を全部数えた。`ice-slide-puzzle.giga-school.com` と Google Fonts の2つだけ |
| 画像は全部で44キロバイト、以前は1.3メガバイト、96パーセント減 | [`AUDIT.md`](../../AUDIT.md) §2 の実測 |
| 記録が端末にもインターネットの向こうにも残らない | `localStorage` `sessionStorage` `indexedDB` `fetch` のいずれも使っていないことを確認。通信先は `index.html` の CSP `connect-src 'self'` で自分自身に限定 |
| 拡大を禁止していない | [`AUDIT.md`](../../AUDIT.md) §3 |
| 濃さと押せる範囲を測って直した | [`AUDIT.md`](../../AUDIT.md) §6 と §7 |

一局にかかる時間は、はっきり測れていません。撮影は自動で操作しているので、
実際に人が遊んだ時間の目安にはならないためです。記事では手数だけを書き、
時間は「数分」とだけ書いてあります。実際に遊んでみて分かったら、そこは書きかえてください。

## 撮り直すときの手順

```bash
npm i --no-save playwright
node .claude/skills/note-article/scripts/serve.mjs . 4180 /Ice_slide-puzzle/   # 別のターミナルで
node .claude/skills/note-article/scripts/capture.mjs <シナリオ> --base http://127.0.0.1:4180/Ice_slide-puzzle/ --out docs/note/images
```

ビルドは要りません。リポジトリの中身をそのまま `/Ice_slide-puzzle/` の下に置いて配ります。
ここを省いてルート直下で配ると、Service Worker と manifest だけ本番と挙動が変わります。

シナリオは `node_modules` の解決の都合でリポジトリの中に置く必要があります。
`.tmp-shots/` のような分かる名前にして、撮り終わったら消してください。
今回のシナリオは納品時に消してあります。

コマは文字では押せないので、`p.raw.locator('#piece-0-2').click()` のように
盤面の座標で指定します。`id` は `piece-<行>-<列>` で、動くたびに付け替わります。
選んだあとは `p.raw.keyboard.press('ArrowDown')` で動かせます。
1手はアニメーションを含めて 700 ミリ秒ほどかかるので、次の操作まで 1.5 秒は空けてください。
