# 画面を撮るときの落とし穴

ここに書いてあるのは、実際に踏んで誤った画像を作りかけたものだけ。
読まずに撮ると、たいてい同じところで転ぶ。

## まず土台を用意する

```bash
npm i --no-save playwright        # package.json には入れない。CI を重くしないため
npm run build
node <skill>/scripts/serve.mjs dist 4180 /<リポジトリ名>/
```

`serve.mjs` の第3引数（ベースパス）を省かない。GitHub Pages で
`https://<user>.github.io/<repo>/` に置かれるアプリは、Service Worker や
manifest が `/<repo>/` という絶対パスを持っている。ルート直下で配ると、
そこだけ本番と挙動が変わってしまう。

シナリオを書いて撮る。

```bash
node <skill>/scripts/capture.mjs shots.mjs --base http://127.0.0.1:4180/<repo>/ --out shots
```

## 1. ふりがな（ruby）を落としてから文字を照合する

子ども向けアプリのボタンは `へやに<ruby>入<rt>はい</rt></ruby>る` のような形をしている。
`textContent` は「へやに入はいる」になるので、「へやに入る」で探しても当たらない。

`capture.mjs` の `click()` は `<rt>` と `<rp>` を落としてから比べるので、
そのまま「へやに入る」で押せる。自分で `page.evaluate` を書くときは、この処理を忘れない。

**押せたかどうかを必ず戻り値で確かめる。** 押せていないのに撮り続けると、
ぜんぜん違う画面のスクリーンショットが並ぶ。`capture.mjs` は押せないと警告を出す。

## 2. アニメーションが終わるまで待つ

600ms では足りない。まだ出ていない要素を撮り落とした。2,200ms で安定した。
`open()` は既定でここまで待つ。画面遷移のあとも 1,500ms 前後は置く。

## 3. お祝いのモーダルが、見せたい画面を隠す

結果画面を撮ろうとすると、レベルアップの演出が手前に出て、肝心の順位表が
ぼやけた背景になってしまう。**閉じてからもう1枚撮る。**

```js
await p.shot('09-levelup');     // お祝いはお祝いで1枚
await p.click('やったー！');
await p.sleep(1500);
await p.shot('10-ranking');     // 本命
```

## 4. 縦に長い画面は、ビューポートを伸ばして1枚に収める

ホーム画面のように上から下まで見せたいものは、`p.resize(390, 1900)` してから撮る。
`fullPage: true` はスクロール容器を持つアプリだと効かないことがあるので、
まずビューポートを伸ばすほうを試す。

内側にスクロール容器がある画面は `p.scrollTo('目当ての文字')` で寄せる。

## 5. 画面に出る URL を本番と同じ見た目にする

QR コードや共有 URL を表示するアプリだと、`http://127.0.0.1:4180/...` が
そのまま写りこむ。記事の画像としては具合が悪い。

撮影のあいだだけ、本番のホスト名をローカルに向ける。

```bash
echo "127.0.0.1 <user>.github.io" >> /etc/hosts
node <skill>/scripts/serve.mjs dist 80 /<repo>/
# --base http://<user>.github.io/<repo>/ で撮る
```

ポート 80 で配るのは、URL に `:8080` を出さないため。
これはアプリの本当の配信先なので、見た目を偽っていることにはならない。

## 6. P2P（みんなであそぶ）を撮るには、シグナリングサーバを手もとに立てる

外部のシグナリングサーバに到達できない環境では、へやを作った瞬間に
「接続エラー」で止まる。`scripts/peer-server.mjs` の先頭に手順が書いてある。

要点は3つ。

- `npm i --no-save peer` して `node <skill>/scripts/peer-server.mjs 9000`
- アプリ側の接続先を `127.0.0.1:9000` に一時的に差しかえ、
  **CSP の `connect-src` に `ws://127.0.0.1:9000` と `http://127.0.0.1:9000` を足す**。
  足さないとブラウザが接続をはじく
- 差しかえたらビルドし直す。**撮影後に必ず戻し、`git status` と `git diff` で
  差分に残っていないか確かめる。** ここを戻し忘れると本番が壊れる

playwright を入れるときは `npm i --no-save playwright peer` のように**まとめて入れる。**
`--no-save` で別々に入れると、あとから入れたほうが前のものを消してしまう。

## 7. マルチプレイは、本当に複数台つないで撮る

`open()` を人数ぶん呼ぶ。それぞれ独立したブラウザのプロファイルになるので、
保存データも混ざらない。合成した画像より、実際につないだ画面のほうが説得力がある。

Qalc の回はリーダー1台と子ども5台で、入室の申しこみから結果発表まで通して撮った。

## 8. 自動で問題を解かせるときは、正答率が不自然にならないようにする

学習アプリの記録画面を撮るには、実際に問題を解く必要がある。
問題文を読んで答えを計算し、キーを順に押す形になるが、次の2つに気をつける。

- **速く押しすぎると誤答が量産される。** 正解した瞬間に次の問題へ進む作りだと、
  押している途中で画面が切り替わり、初回正答率が数パーセントまで落ちた。
  1問ごとに 900ms ほど置いて、答えを入れ終えてから 150ms 待って決定を押す
- **わざと数問だけまちがえる。** 「まちがえた問題」の一覧や復習の機能を
  撮りたいなら、全問正解では何も出ない。最初の2問だけずらして答え、
  そのあと正しく答え直す

## 9. 撮影用のスクリプトはリポジトリの中に置き、終わったら消す

`node_modules` の解決の都合で、シナリオファイルはリポジトリの中に置くことになる。
`.tmp-shots/` のような分かる名前にして、**納品前に必ず消す。**
`git status` にスクリプトが残っていないか確かめる。

## 10. 記事に載せる機能は、撮る過程で必ず実機を踏む

Qalc の回は、これで本番が壊れていることに気づいた。
「じんとりバトル」を撮ろうとしたら、開始した瞬間に全端末がまっ白になった。
インポートもれで、そのモードに入ると必ず落ちる状態だった。

**動かない機能を紹介する記事を出してはいけない。**
見つけたら、記事より先にそれを報告する。直せるなら直して、
別のコミットに分けたうえで「公開の前にこの修正を反映してください」と伝える。

撮影は、いちばん丁寧な受け入れテストでもある。
