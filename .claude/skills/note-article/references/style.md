# 文体ガイド（連載「教室で使えるかもしれないもの作り」）

書き手は GIGA山。小学校の先生が、同じ小学校の先生に向けて、自分の作ったものを紹介する連載。
読み手は忙しい先生方で、「ICTは難しそう」と感じている層にも届かせたい。

## 立ち位置

作者本人が書く。だから「作った理由」「あえてそうしなかったこと」を書ける。
そこがこの連載の強みなので、機能の説明だけで終わらせず、なぜその作りにしたのかを添える。

いっぽうで、**教室での出来事を実体験として書いてはいけない。**
作者の実践記録ではないので、「使ってみたら子どもたちが〜」と書くと嘘になる。
書けるのは「こうなればいいと思って作った」「〜だと思います」まで。
実際の授業での様子は、書き手が自分で足すところ。

## 厳守ルール

書き手が使っている執筆プロンプトの指定。ここは崩さない。

1. **太字（`**`）を使わない。** 装飾ではなく文章の力で強調する
2. **斜体・表・区切り記号を使わない。** `→` `／` `：` `▲` `▶` はすべて禁止
3. **Markdown は見出し（`#`）だけ。** note のエディタに素直に貼れることを優先する
4. **箇条書きは手順のときだけ。** それ以外は文章で書く。並べれば伝わるわけではない
5. **かっこの多用を避ける。** 補足したくなったら、次の一文にする
6. **専門用語は日常の言葉に。** デプロイ、変数、配列、関数、ローカルストレージ、WebRTC といった
   言葉は出さない。「公開の設定」「その端末のなかだけに残ります」と言いかえる
7. **絵文字は見出しだけ。** 本文には入れない
8. **定型の前置きを書かない。** 「結論から言うと」「〜を解説します」は使わない
9. **抽象語を避ける。** 「重要」「最適」ではなく「〜が楽になる」「丸付けに追われなくなる」

## 呼びかた

- 子どものことは「子どもたち」。「児童」は硬いので使わない
- 読み手は「先生」「先生方」
- 「です・ます」調

## 構成

見出しはこの並びを基本にする。note は見出しから目次を自動で作るので、
ここがそのまま記事の骨格になる。

```
# 教室で使えるかもしれないもの作り #◯ （キャッチーなタイトル）「アプリ名」

## 🏫 はじめに
## 📱 このアプリでできること
## ✨ 導入のメリット
## 🛠️ 【管理者向け】導入手順
## 📖 【利用者向け】使い方のガイド
## 📝 まとめ
```

そのアプリの目玉が既存の見出しに収まらないときは、📱 と ✨ のあいだに足す。
たとえば Qalc の回では「💡 鉛筆が止まった子を助ける「かんがえるどうぐ」」と
「🤝 クラス全員で挑む「ボスバトル」と「じんとりバトル」」を足した。
足しすぎると目次が散らかるので、多くて2本まで。

### タイトルの型

`「（読み手が困っていること）」（アプリの持ち味）アプリ「名前」` の形。

- #9 … 「4択」じゃ届かない定着を。経験値でハマる計算学習アプリ「Qalc（カルク）」
- 今回 … 「せんせい、わかりません」で止まらない。考える図が出てくる計算学習アプリ「Qalc（カルク）」

**連載番号は推測で埋めない。** 分からなければ `#◯` のままにして、
納品時に「ここだけ直してください」と伝える。番号を間違えると連載が壊れる。

### 🏫 はじめに

読み手が抱えている困りごとに、まず寄りそう。
「〜ではありませんか」「〜ですよね」「〜ではないでしょうか」と問いかける形が合う。

そのあとで、このアプリがその困りごとにどう効くのかを一言で置き、URL を出す。

前作がある場合は、ここで前作との地続きを作る。
「以前この連載で紹介した◯◯を、まるごと作り直しました」と書けると、
連載の読者にとって記事の意味がはっきりする。

### 📱 このアプリでできること

機能を並べるのではなく、子どもや先生が実際に使っている場面が浮かぶように書く。
画面のスクリーンショットはここから入れはじめる。

### ✨ 導入のメリット

「三つのいいことが期待できます。」で始めて、
「一つ目は、〜ことです。」「二つ目は、〜」「三つ目は、〜」と続ける型。
それぞれ一段落。得られるのは機能ではなく「心のゆとり」と「教育効果」。

### 🛠️ 【管理者向け】導入手順

情報担当の先生に確認されることを、先に全部書いておく。
校内フィルタリングで許可が必要なアドレス、個人情報の扱い、共用端末での注意、
端末ごとの癖。ここがしっかりしていると、導入の相談が一往復で済む。

### 📖 【利用者向け】使い方のガイド

ここだけは番号つきの手順で書く。迷いようがない粒度にする。

### 📝 まとめ

ICT を使うことで生まれる「子どもと向き合う時間」の話でしめる。
効率化そのものが目的ではない、という筋を通す。

最後は挑戦する先生への応援で終わる。#9 の結びはこれ。

> 一歩踏み出そうとする先生を、私はいつでも全力で応援しています。

## 画像のキャプション

画像の直後に、短い一行を置く。装飾記号は付けない。

```
![ホーム画面](images/01-home.png)

トップページ。レベルと称号、コイン、連続学習日数が一画面にまとまっています。
```

名詞だけの短いものと、一文の説明を混ぜると単調にならない。
note ではキャプション欄に移すので、本文から浮いていて問題ない。

## 分量

7,000〜9,000字あたり。#9 は約5,000字だったが、画面の点数が増えるぶんは伸びてよい。
見出しで区切られていれば、読み手は必要なところだけ読める。

## やりがちな失敗

- 太字を散らして、広告のようになる
- 「〜できます」を並べて、なぜそうしたのかを書き忘れる
- 表で情報を詰めこむ（note では表示されないので、そもそも意味がない）
- 効果を言い切る（「教室でいちばん盛り上がる時間になる」）。作者の見立てとして書く
- 記号（`→` `／`）でつないで、文章になっていない
- 導入手順を後回しにする。ここが読まれないと、そもそも使ってもらえない
